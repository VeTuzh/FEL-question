# 个人 Codex 项目模板

这是一个用于跨电脑协作的通用项目模板，适用于 Codex、GitHub Desktop、Git 和 Git LFS。

模板将项目目标、进度、长期决策和资料索引保存在仓库中，使不同电脑上的新会话能够从项目文件恢复上下文，而不依赖旧聊天记录。

## 从模板创建新项目

1. 在 GitHub 仓库页面点击 **Use this template**。
2. 选择 **Create a new repository**。
3. 填写新项目名称，并按需要选择 Private 或 Public。
4. 在工作电脑上使用 GitHub Desktop 克隆新仓库。
5. 将仓库中的占位内容替换为新项目的真实信息：
   - `MISSION.md`：目标、成功条件、范围和约束。
   - `STATUS.md`：当前里程碑、已完成工作、下一步和阻塞项。
   - `NOTES.md`：重要发现、决策、偏好和假设。
   - `RESOURCES.md`：资料、证据和缺口索引。
   - `AGENTS.md`：项目专属工作规则。
6. 检查 `.gitignore` 和 `.gitattributes` 是否适合该项目。
7. 提交并推送初始化修改。

## 推荐目录

| 目录 | 用途 |
|---|---|
| `references/` | 原始参考资料和文献 |
| `assets/` | 正式交付物使用的图片和素材 |
| `outputs/` | 正式交付物和发布资料包 |
| `work/` | 可编辑源稿、脚本和处理中间材料 |
| `tmp/` | 可删除、可重新生成的临时文件；默认不提交 |
| `lessons/` | 经验证的问题、经验和改进记录 |

## 每次开始工作

1. 打开 GitHub Desktop，确认仓库和分支正确。
2. 确认没有来源不明的本地修改。
3. 点击 **Fetch origin**；如出现 **Pull origin**，先拉取远端更新。
4. 让 Codex 读取 `AGENTS.md`、`MISSION.md`、`STATUS.md`、`NOTES.md` 和 `RESOURCES.md`，进行只读状态恢复。
5. 明确本轮任务、允许修改的范围和验证标准。

## 每次结束工作

1. 保存并验证实际修改。
2. 在 `STATUS.md` 记录实际完成项、验证结果、下一步和阻塞项。
3. 将会改变后续路线的重要决策写入 `NOTES.md`。
4. 新增关键资料时更新 `RESOURCES.md`，并使用仓库相对路径。
5. 在 GitHub Desktop 检查变更内容。
6. 提交并推送；确认工作区重新显示 **No local changes**。

## Git LFS

模板默认使用 Git LFS 管理 Office 文档、PDF、压缩包、常见位图、音视频和部分大型二进制格式。创建新项目后，先确认每台电脑均已安装 Git LFS。

如果项目只包含代码和小型文本，可以删除 `.gitattributes` 中不需要的 LFS 规则；已经提交到 LFS 的文件不要仅通过删除规则来迁移。

## 跨电脑注意事项

- 离开一台电脑前先提交并推送；换到另一台电脑后先拉取再修改。
- 不要在两台电脑上同时保留未提交的同一文件修改。
- 仓库文件使用相对路径，不记录个人主目录、临时附件目录或浏览器下载目录。
- 不提交密码、令牌、Cookie、浏览器配置或其他凭证。
- 大文件下载异常时，先检查 Git LFS，不要把指针文本当作真实文件编辑。

## 首次恢复提示词

可在新电脑或新会话中使用：

```text
请先进行只读项目恢复。读取 AGENTS.md、MISSION.md、STATUS.md、NOTES.md 和 RESOURCES.md，并检查当前 Git 分支、工作区状态和最近提交。仓库文件和实际验证结果是事实来源。报告项目目标、当前里程碑、已完成工作、下一步、阻塞项和待确认事项。不要修改文件，不要提交或推送。
```
